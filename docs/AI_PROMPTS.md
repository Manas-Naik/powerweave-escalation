**Module:** `src/controllers/escalation.controller.ts`

```

CONTEXT: We are building the Smart Task Escalation Engine for Powerweave.

2. GET /escalations/:id/history - get audit history

- Export validation schemas separately so they can be unit tested
- No business logic in the controller — delegate to service layer
- Use try/catch with next(err) for all error handling
- Add JSDoc to every exported class method
- TypeScript strict mode

OUTPUT: A single TypeScript file: src/controllers/escalation.controller.ts
```

## Prompt 2 — Escalation Service (State Machine)

**Module:** `src/services/escalation.service.ts`

```
ROLE: You are a senior TypeScript backend developer implementing domain logic.

CONTEXT: Build EscalationService for the Powerweave escalation engine.
It orchestrates:
- Task existence and status validation
- Duplicate escalation detection (prevent two open escalations per task)
- Manager resolution (from input or team default)
- Prisma DB writes
- Async notification dispatch (non-blocking, errors should not propagate)
- Audit logging

State machine transitions allowed:
OPEN → IN_PROGRESS
OPEN → RESOLVED  
IN_PROGRESS → RESOLVED
RESOLVED → CLOSED

RULES:
- VALID_TRANSITIONS must be a const map (not nested if-else)
- Notification dispatch must be fire-and-forget (non-blocking)
  with failure logged but not re-thrown
- Use AppError class for all thrown errors (statusCode, code, message)
- Prisma is injected via constructor (not imported directly) for testability
- JSDoc on all public methods including @throws documentation
- No HTTP-specific imports (Request, Response are controller concerns)

OUTPUT: src/services/escalation.service.ts
```

**Generated output:** Service with state machine map, `createEscalation()`, `updateStatus()`, `getHistory()`, and private `resolveTeamManager()`.

## Iteration Example: Fixing a Generated Test

On the first generation of `notification.trigger.test.ts`, the AI generated:

```typescript
// ❌ AI first attempt — non-deterministic
it("should set sentAt to current time", async () => {
  await service.dispatch(input);
  const call = mockPrisma.notification.create.mock.calls[0][0];
  expect(call.data.sentAt).toBeInstanceOf(Date);  // passes but doesn't verify exact value
});
```

**Correction prompt sent:**

```
The sentAt test is non-deterministic — it only checks instanceof Date,
not the actual value. Mock Date globally to FIXED_DATE = 
new Date("2025-01-15T10:00:00.000Z") and assert the exact value.
Show jest.spyOn(global, 'Date') pattern.
```

**AI corrected output:**

```typescript
// ✅ Corrected — deterministic
const FIXED_DATE = new Date("2025-01-15T10:00:00.000Z");
beforeEach(() => {
  jest.spyOn(global, "Date").mockImplementation(() => FIXED_DATE as unknown as string);
});
afterEach(() => { jest.restoreAllMocks(); });

it("should set sentAt to the mocked current time", async () => {
  await service.dispatch(input);
  expect(mockPrisma.notification.create).toHaveBeenCalledWith(
    expect.objectContaining({
      data: expect.objectContaining({ sentAt: FIXED_DATE }),
    })
  );
});
```

This demonstrates the iterative AI loop: initial generation → identify issue → targeted correction prompt → verified fix.
